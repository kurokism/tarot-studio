# タロット占い・演出アプリ 要件定義書

## 1. 文書概要

### 1.1 背景

VTuber・配信者がタロット占いを配信で行う場合、実際のタロットカードを使用することで、カードを引く動作やカードそのものを視覚的な演出として活用できる。

一方で、VTuberの配信では実写映像を配信画面に表示しないケースも多く、実際に使用しているカードやその配置を視聴者へ直接見せることが難しい。

そこで、実際のカードを使って占いを行いながら、引いたカードやその配置、占い結果をアプリケーション上で再現し、VTuberの配信画面に適した形で表示・演出できるようにする。

また、実物のカードを使用しない場合にも利用できるよう、アプリケーション上でカードをランダムに引く機能にも対応する。

### 1.2 開発目的

- 実際のタロットカードを使用した占い結果を、配信画面上で表示できるようにする
- 配信に適したカードの配置・展開・反転等の演出を提供する
- 様々なデッキ・スプレッドに対応できる汎用的な構造とする
- ユーザーがカードやスプレッド等をカスタマイズできるようにする
- 将来的な機能追加・拡張に対応できる設計とする

---

## 2. 想定利用者

### 2.1 主な利用者

- VTuber
- YouTuber
- ライブ配信者
- タロット占いを配信コンテンツとして利用する配信者

### 2.2 副次的な利用者

- タロットカードを持っていない人
- タロット占いに興味があり、アプリで占いを行いたい人

### 2.3 想定利用シーン

#### パターンA：実物のカードを使用した占い

1. 配信者が実際のタロットカードを引く
2. アプリ上で使用するスプレッドを選択する
3. 引いたカードをアプリに入力する
4. 正位置・逆位置を入力する
5. アプリが占い結果を表示する
6. 必要に応じてカード演出を行う
7. OBSを通して配信画面に表示する

#### パターンB：アプリによるランダム占い

1. デッキ・スプレッドを選択する
2. アプリ上でカードをランダムに引く
3. 正位置・逆位置を決定する
4. 結果を表示する
5. 必要に応じて演出を行う
6. 配信する場合は、OBSを通して配信画面に表示する

## 3. システム概要

### 3.1 対応環境

本システムは、以下のOSを対象とする。

- Windows
- macOS

### 3.2 システム構成

本システムは、以下の機能で構成する。

```text
カード管理 ──┐
             │
デッキ管理 ──┤
             ↓
スプレッド管理
             ↓
      ┌──────┴──────┐
      ↓             ↓
   手動占い       ランダム占い
      └──────┬──────┘
             ↓
          占い履歴
             │
             ↓
           演出
             ↓
         OBS表示

設定 ─→ アプリ全体の各種設定
```

### 3.3 占い方式

本システムでは、以下の2種類の占い方式に対応する。

#### 手動占い

実物のタロットカードを使用し、実際に引いたカードの情報をアプリへ入力する。

#### ランダム占い

アプリ上でカードをランダムに選択し、正位置・逆位置を含めて占い結果を決定する。

## 4. 機能要件

本システムは、以下の機能を提供する。

| ID  | 機能       | 機能概要 |
|-----|------------|----------|
| F00 | 設定       | アプリ全体の各種設定を行う |
| F01 | カード管理 | カード、画像、意味、個人メモ等を管理する |
| F02 | デッキ管理 | 使用するカードの組み合わせをデッキとして管理する |
| F03 | スプレッド管理 | 占いパターン、カード配置、各位置の意味等を管理する |
| F04 | 手動占い | 実際に引いたカードをアプリへ入力して占う |
| F05 | ランダム占い | アプリ内でカードをランダムに引いて占う |
| F06 | 演出 | シャッフル、カード移動、反転、表示等の演出を行う |
| F07 | OBS表示 | 配信画面向けの表示を行う |
| F08 | 占い履歴 | 過去の占い結果を記録・確認する |

---

## 5. 各機能の概要

### 5.1 F00 設定

アプリのサウンドに関する設定やヘルプを提供する。

- サウンドに関する設定を変更できる
- アプリの操作方法や機能に関するヘルプを確認できる

### 5.2 F01 カード管理

タロットカードごとの情報を管理する。

管理する情報：
- カード名
- カード画像
- 正位置の意味
- 逆位置の意味
- 個人メモ

機能：
- カードの追加・編集・削除

### 5.3 F02 デッキ管理

使用するカードの組み合わせをデッキとして管理する。

管理する情報：
- デッキ名
- デッキに含めるカード

機能：
- デッキの作成・編集・削除
- デッキに含めるカードの追加・削除

### 5.4 F03 スプレッド管理

タロット占いで使用するスプレッドを管理する。

管理する情報：
- スプレッド名
- 使用するカード枚数
- 各位置の名称
- 各位置の意味
- カードの配置

機能：
- スプレッドの追加・編集・削除

### 5.5 F04 手動占い

実際に引いたタロットカードの結果をアプリへ入力し、占いを行う。

- 使用するデッキを選択できる
- 使用するスプレッドを選択できる
- 実際に引いたカードを入力できる
- 正位置・逆位置を入力できる
- 入力した結果を確定できる
- 確定した占い結果を表示できる

### 5.6 F05 ランダム占い

アプリ上でカードをランダムに選択し、占いを行う。

- 使用するデッキを選択できる
- 使用するスプレッドを選択できる
- デッキに含まれるカードからランダムにカードを選択できる
- カードの正位置・逆位置を含めてランダムに結果を決定できる
- 決定した占い結果を表示できる

### 5.7 F06 演出

占い結果を配信等で表示するためのカード演出を行う。

- カードのシャッフル演出を行える
- カードの移動・配置演出を行える
- カードの反転演出を行える

### 5.8 F07 OBS表示

占い結果を配信画面上で表示する際のカード演出を行う。

- 占い結果を配信画面向けに表示できる

### 5.9 F08 占い履歴

過去に行った占いの結果を記録・確認する。

- 占いを行った日時を記録する
- 使用したデッキを記録する
- 使用したスプレッドを記録する
- 各位置に配置されたカードを記録する
- 各カードの正位置・逆位置を記録する
- 過去の占い結果を確認できる

## 6. データ要件

本システムでは、以下のデータを管理・保存する。

### 6.1 カードデータ

タロットカードごとに以下の情報を管理する。

- カードID
- カード名
- カード画像
- 正位置の意味
- 逆位置の意味
- 個人メモ

### 6.2 デッキデータ

デッキごとに以下の情報を管理する。

- デッキID
- デッキ名
- デッキに含まれるカード

### 6.3 スプレッドデータ

スプレッドごとに以下の情報を管理する。

- スプレッドID
- スプレッド名
- 使用するカード枚数
- 各位置の名称
- 各位置の意味
- カードの配置

### 6.4 占い結果データ

占い結果ごとに以下の情報を管理する。

- 占い日時
- 使用したデッキ
- 使用したスプレッド
- 各位置に配置されたカード
- 各カードの正位置・逆位置

### 6.5 設定データ

アプリの設定に関するデータを管理する。

- サウンドに関する設定

### 6.6 データの永続化

カード、デッキ、スプレッド、占い結果、設定等のデータは、アプリケーション終了後も保持できるものとする。

## 7. 非機能要件

### 7.1 OS互換性

- WindowsおよびmacOSにおいて、主要な機能を利用できる
- OSによる機能や操作性の差を可能な限り抑える

### 7.2 操作性

- 配信中に操作することを想定する

### 7.3 性能

- 通常の操作において、実用上問題のない応答速度で動作する

### 7.4 拡張性

- カード、デッキ、スプレッドを追加・変更できる構造とする
- 新しい占い方式や機能を追加できる構造とする
- 将来的なWeb版等への展開を考慮した構造とする

### 7.5 保守性

- 機能ごとに責務を分離し、機能追加・変更の影響範囲を抑える

### 7.6 信頼性

- アプリケーションの異常終了等が発生した場合でも、保存済みのデータを可能な限り保持する
- アプリケーションの更新によって、ユーザーが登録したデータを失わないようにする

### 7.7 セキュリティ

- ユーザーが登録したデータを、不要に外部へ送信しない
- 外部サービスとの通信を必要としない機能については、ローカルで完結する構成とする

## 9. MVP

### 9.1 MVP対象

以下の機能をMVPの対象とする。

- F00 設定
- F01 カード管理
- F02 デッキ管理
- F03 スプレッド管理
- F04 手動占い
- F06 演出
- F07 OBS表示
- F08 占い履歴

### 9.2 MVPの範囲

- 大アルカナ22枚を対象とする
- 1枚引き、3枚引きに対応する
- 実物のタロットカードを使用した手動占いに対応する
- 基本的なカード演出に対応する
- OBSを通した配信画面への表示に対応する
- 占い結果の保存・確認に対応する

### 9.3 MVP完成条件

以下を一連の流れとして実行できることをMVPの完成条件とする。

1. デッキとスプレッドを選択する
2. 実際に引いたカードを入力する
3. 正位置・逆位置を含む占い結果を確定する
4. 占い結果を表示する
5. カード演出を行う
6. 占い結果をOBSを通して配信画面に表示する
7. 占い結果を履歴として保存・確認する
